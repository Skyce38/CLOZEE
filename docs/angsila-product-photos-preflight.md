# ตรวจ Angsila ก่อนอัปเดตรูปสินค้า

31 ตุลาคม 2569 ผู้ใช้อนุมัติให้ตรวจ สำรอง และติดตั้งฟีเจอร์รูปสินค้า หลังจากผล Local/CI ผ่านแล้ว

## ผลตรวจจริง

| รายการ | ผล |
| --- | --- |
| PHP ในบริบทเว็บ CLOZEE | 8.4.27 |
| GD | ไม่ได้เปิดใช้งาน |
| EXIF / fileinfo | เปิดใช้งาน |
| PHP เขียน private storage เดิม | ไม่ได้ |
| สิทธิ์ directory storage | 0755; เจ้าของต่างจากบัญชีที่ PHP ทำงาน |
| PHP เขียน home เพื่อสร้าง backup | ไม่ได้ |
| Migration รูปสินค้า | ยังไม่รัน |
| เปลี่ยน application code / CSS / JS บนเซิร์ฟเวอร์ | ยังไม่ดำเนินการ |
| สำรองก่อน migration | ยังไม่ดำเนินการ เพราะ preflight ไม่ผ่านและยังไม่เริ่มอัปเกรด |
| เว็บไซต์เดิมหลังตรวจ | HTTP/security checks ผ่าน 17/17 |
| ตัวตรวจชั่วคราว | ย้ายออกจาก public_html ไปเก็บแบบ disabled ใน private; URL เดิมตอบ 404 |

ตัวตรวจจำกัดเฉพาะงานอัปเกรดที่เตรียมไว้ ใช้ token ชั่วคราวและวันหมดอายุ ไม่รับคำสั่ง shell หรือ SQL จาก request ไม่มีการอ่านหรือแสดงรหัสผ่านในการตรวจครั้งนี้ ค่า PHP/GD และสิทธิ์มาจากกระบวนการ PHP ของเว็บไซต์จริง ไม่อนุมานจาก phpMyAdmin

หยุดก่อน backup/migration/แทนที่โค้ด การที่ schema และภาพผ่านในเครื่องหรือ GitHub CI ไม่ได้หมายความว่า Angsila รองรับ การแก้สิทธิ์เป็น world-writable ไม่ใช่ขั้นตอนที่ดำเนินการในงานนี้

## ทางเลือกที่ต้องตัดสินใจ

1. ขอผู้ดูแลเปิด GD ที่รองรับ JPEG/PNG/WebP และจัดพื้นที่ private ให้บัญชีเว็บเขียนได้อย่างจำกัด จากนั้นตรวจใหม่ก่อนสำรองและอัปเดตตาม migration เดิม
2. ปรับการเก็บภาพให้ใช้ฐานข้อมูล และออกแบบการตรวจไฟล์ที่รองรับ runtime นี้ ต้องแก้ implementation/schema ทดสอบทั้งสภาพแวดล้อมที่มีและไม่มี GD แล้วนำ SQL ใหม่ให้ตรวจและอนุมัติก่อนเปลี่ยนฐานข้อมูลจริง

ระหว่างรอการตัดสินใจ เว็บไซต์ Angsila ยังคงเป็นรุ่นเดิม ฟีเจอร์รูปสินค้าใน source `8c73cc7` ยังไม่พร้อมติดตั้งบนสภาพแวดล้อมที่ตรวจพบ
