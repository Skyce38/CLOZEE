# Implementation decisions

These resolve draft v0.3 ambiguities; they are implementation choices, not additional lecturer requirements.

1. PHP 8.1+ and native PDO MySQL prepared statements, without a server build framework. Local verification: PHP 8.5.12 / MariaDB 11.4.9. MySQL 8.0.16+ is the target for enforced CHECK constraints; Angsila compatibility is still unverified.
2. Preserve the original schema in `reference/schema-v0.3.sql`. Reviewed schema adds variant version/active flags, checkout idempotency key and request hash, quantity/money checks, a status history table and transient login throttling table: 10 tables total.
3. One shop per user, one shop per checkout, up to 20 variant lines, 1–99 units per line. A shop owner cannot buy from their own shop. A product supports up to 12 stable size labels; existing labels are not renamed or removed, but may be deactivated. Creating a replacement size is explicit.
4. Cart is server-side session state. Price and delivery fee are taken from server-side data at final checkout, never from posted totals. Monetary calculations use integer satang. Per-unit prices and order totals are capped at 9,999,999.99 THB at the application layer.
5. Local delivery is a recorded fulfillment choice, with a configurable 30.00 THB fee per order. Pickup is free. No geographical validation, payment processing, driver allocation or shipping API. Buyers include only the contact/location details they choose to share with the shop.
6. Checkout locks buyer, shop, products and variants in a consistent order, rechecks activity/stock and commits snapshots/order/stock/audit together. Unique buyer/key plus payload fingerprint protects repeated submissions. Three transaction attempts handle deadlocks. Variant versions protect against stale seller stock edits.
7. Seller transitions: pending → confirmed → preparing → ready_for_pickup (pickup) or out_for_delivery (delivery) → completed. Cancellation is allowed only from pending/confirmed/preparing and restores stock once inside the same locked transaction. Terminal states cannot be changed. Only the relevant shop owner may mutate status.
8. Products with no order references can be physically deleted with their variants in a transaction. Products referenced by any order cannot be physically deleted and may be deactivated. Historical order snapshots remain unchanged. Shops deactivate rather than being destroyed.
9. One primary image selected from four bundled demo photographs in P0. Customer image uploads and multiple-image management are not implemented. This keeps file-upload attack paths outside the current release and is disclosed as a limitation, rather than claiming a general upload feature.
10. Text-only chat was implemented after local core tests passed, as authorized by the user's request. It is not realtime: users refresh to see replies. Only the conversation's buyer or current shop owner can read/send. One thread per buyer/product is reused. Show latest 100 messages/threads. Angsila deployment remains a separate unpassed gate.
11. Cookie HttpOnly/SameSite=Lax, strict PHP session mode, rotation after login and registration, 30-minute idle expiry, POST+CSRF logout. Secure cookies default ON and are disabled only in the private loopback HTTP config. Database-backed login throttle: 5 failed attempts/account+IP or 40/IP in 15 minutes. No raw IP/password is stored in throttle records.
12. No real accounts, Google Sheets passwords or customer data are used. Demo emails use `example.test`; seed script generates random credentials into ignored, non-public `storage/demo-accounts.json`. Seed SQL contains hashes only. Never deploy demo accounts as production users.
13. Public web root is `public/`; `app`, `database`, `scripts`, `tests`, `docs` and `storage` must stay outside the served root. Deployment mapping and private config require target-specific verification before approval. No production migration has been authorized or run.
14. No admin/rider/SSO roles. Seller overview is basic P0 navigation; analytics dashboard and multiple images remain deferred. Product catalog is paginated; shop listing and order/thread history have explicit current limits (100 records). Data export/full-text search are not claimed.
